## Summary

The change implements the complete v1 codec, canonical fixtures, a bounded latest-state channel, and a cancellable UDP receive loop while deliberately keeping production admission closed. ## Minor

### 🟡 The PC receive path does not reject messages sent in the wrong direction, `pc_agent/src/network.rs:100`

**Problem**: Every valid non-state datagram is passed to `Handler::control`, and `DenyAll` returns `None`. Consequently a client can send `HELLO_ACK`, `PAIR_ACCEPT`, `PAIR_REJECT`, or `STATUS` to the PC and the runtime records only a successful codec decode; there is no refused/invalid outcome. The normative receiver order explicitly includes expected direction/state-transition validation, and no test covers a PC-directed message arriving at the PC.

**Why it matters**: This makes the transport contract incomplete and its diagnostics cannot distinguish ignored wrong-direction traffic from an expected control request. Once session logic is added, silently accepting the direction at this boundary makes state-transition mistakes easier to introduce.

**Suggested fix**: Give the handler/receiver an explicit ignored-or-refused control outcome, reject PC-to-phone message types on the PC receive path, and add an integration test proving they cannot produce a reply or state update and are counted as rejected.

### 🟡 One invalid handler reply terminates the UDP listener, `pc_agent/src/network.rs:101`

**Problem**: A `Message` returned by `Handler::control` is encoded inside the receive loop, and any range/reserved-field error is converted to `io::Error` and returned from `run`. The public handler contract does not require or enforce a prevalidated reply, and the test handler covers only a valid reply.

**Why it matters**: A future production handshake handler can accidentally construct one invalid response from otherwise harmless remote input and bring down the entire listener. That turns an internal validation failure into loss of service rather than a contained refusal and diagnostic.

**Suggested fix**: Treat reply-encoding failure as a counted internal/refused error and continue receiving, or change the handler boundary so it can return only an already validated encoded packet. Add a handler test that deliberately returns an invalid reply and verifies the socket remains responsive.
